# SupportDesk Lite — подготовка к обсуждению

Проект показывает цикл: интерфейс → HTTP API → валидация → база данных → обновление интерфейса. Прежде чем добавлять в CV, запусти приложение, прочитай основные функции и самостоятельно внеси небольшое изменение.

## Демонстрация за две минуты

1. Создай заявку о мониторе с высоким приоритетом.
2. Найди её по слову из описания.
3. Переведи в `In progress`, затем `Resolved`: счётчик незакрытых срочных заявок уменьшится.
4. Перезапусти сервер: данные сохранятся.
5. Запусти `python -m unittest -v` и объясни один тест.

## Вопросы

| Вопрос | Объяснение |
| --- | --- |
| Почему SQLite? | Один файл, без отдельного сервера. Достаточно для локального демо. |
| Почему Python без фреймворка? | Небольшой масштаб позволяет показать HTTP напрямую. Для публичного сервиса удобнее зрелый фреймворк. |
| Где валидация? | `TicketStore.validate`: проверяет объект, поля, длины строк и допустимые статусы/приоритеты. |
| Как предотвращается SQL injection? | Значения передаются через `?`; имена полей берутся из проверенного набора. |
| Почему текст безопасно отображается? | `node()` использует `textContent`. HTML пользователя отображается как текст. |
| Что делает PATCH? | Меняет переданные поля, сохраняя остальные. |
| Как работает поиск? | `LIKE` по трём полям; статус добавляется через `AND`. `%` и `_` экранируются. |
| Зачем `requestVersion`? | Ответы поиска приходят в разном порядке. Интерфейс обновляет только последний запрос. |
| Почему отдельные соединения SQLite? | HTTP-запросы выполняются в потоках. Соединения не разделяются между потоками. |
| Что проверяют тесты? | Реальные HTTP-запросы на свободном порту с временной БД; ошибки, сохранность и переходы состояния. |

## Ограничения

Нет авторизации, истории, вложений и защиты от конфликтующих правок. Все заявки загружаются сразу, статистика считается в Python. Это компактный учебный масштаб; сервер слушает только `127.0.0.1`.

## Самостоятельная доработка

- Добавь фильтр приоритета: API, интерфейс и поведенческий тест.
- Добавь карточку закрытых заявок.
- Сделай пагинацию и SQL `COUNT` вместо подсчёта в Python.
- Продумай историю: отдельная таблица событий и запись в той же транзакции.

Описывай только то, что понимаешь и делал. Не заявляй вымышленный коммерческий опыт или работу с реальными клиентами.
